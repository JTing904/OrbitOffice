# Writing a README

## Structure
1. **Name and one sentence**: what it is and who it is for.
2. **Screenshot or short example** of it working (if there is UI or output to show).
3. **Features**: 3-7 bullets, each a concrete thing the user can do.
4. **Install / get started**: exact commands or download steps, tested where possible. State requirements (OS, versions).
5. **Usage**: the most common tasks, with examples.
6. **Configuration** (if any): options and defaults.
7. **Development**: how to build and run tests.
8. **Limitations / known issues**: be honest.
9. **License**.

## Rules
- Every command must work as written. Run it if you can.
- Prefer short sentences and real examples over adjectives.
- Keep it in the user's language unless the project is aimed at an international audience.
