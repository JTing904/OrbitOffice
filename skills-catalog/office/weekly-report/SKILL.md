# Weekly report

Write in the user's language.

## Sources
Look at what actually happened: the project's history, changed files, finished tasks, git log for the week if available. Do not guess.

## Format
1. **Summary**: 2-3 sentences, the most important outcome first.
2. **Done this week**: bullets with results, not activities ("Login page live, error rate down from 3% to 0.5%", not "Worked on login").
3. **In progress**: what, how far, expected finish.
4. **Next week**: 3-5 priorities.
5. **Risks / blockers**: what could slip and what is needed from whom.

## Rules
- Numbers and links where possible.
- One page. Save to docs/weekly/<year>-W<week>.md.
