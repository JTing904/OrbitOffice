# OrbitOffice

**给你的 AI 团队一间 3D 办公室。** 你说要做什么，一组 AI 员工就会规划、动手、互相检查、交接给下一位，把真正的文件写进你选的文件夹。你能看到他们坐在工位上干活，能和他们聊天，重要的事由你批准。

自带一支写软件的团队；但团队只是一组 Markdown 文件，你可以自己写员工和办公室，用来做内容、营销、调研，或任何产出是文字的工作。

## 它能做什么

- **真的干活。** 员工在你的工作文件夹里查看、搜索、读写文件；你允许的话，还能运行命令（跑测试、跑脚本），并通过 MCP 连接器使用外部工具。
- **能查实时资料。** 员工会上网搜索、读网页（DuckDuckGo，不用 Key），查新闻、趋势、价格、最新文档，并注明来源。需要电脑上装有 [uv](https://docs.astral.sh/uv/)。
- **会自己检查的团队。** 员工会判断要不要交给同事继续，发现问题会打回去，做不了或不该做的会停下并说明原因。每次交接都可以设成要你批准。
- **自己搭办公室。** 每个员工是一个 `.md` 文件：开头是设置，正文是职责说明。可以新增、编辑、导入、直接拖进来；也可以用一句话描述需求，让 AI 帮你搭好整个办公室。
- **技能库。** 大脑里存着团队共用的做事方法（技能），格式和 Claude 的技能（`SKILL.md`）一样，网上分享的技能可以直接导入。员工平时只看技能的名字和简介，任务需要时才读全文。
- **群聊讨论。** 在群聊里抛一个话题，几位员工从各自岗位的角度讨论，最后由主持人总结并给出任务清单，一键按顺序开始。
- **项目记忆。** 每做完一件事都记在项目文件夹里。员工接新任务前，会先找相关的旧工作，并读团队的共享笔记；笔记太长时会自动整理成摘要。
- **免费的 AI 池。** 可以同时接多家的 API Key（Google Gemini、NVIDIA NIM、Groq、OpenRouter、本地 Ollama，或任何兼容 OpenAI 的接口）。OrbitOffice 会实测每个模型，做任务用最强的、聊天用轻的，额度用完自动换下一个。
- **内置本地 AI。** 不用 Key、不用联网：OrbitOffice 会检测你的显卡、内存和硬盘，推荐一个在你电脑上跑得动的开源模型（Qwen3.5，2B 到 35B），一键下载就能用，不需要装 Ollama。
- **一切由你掌控。** 三种权限模式（手动、自动、完全访问）、按岗位限制能写的文件、危险命令一律拦下、有风险的操作先问你。API Key 加密保存在你的电脑上，界面里永远不显示完整的 Key。

## 开始使用

1. 下载最新的 Windows 版本，运行安装程序。
2. 打开 **设置 → AI 池**。可以直接启用 **本地 AI**（一键，在你的电脑上跑），或者选一家服务商、粘贴它的 API Key。免费的就够用：
   - Google Gemini：<https://aistudio.google.com/apikey>
   - NVIDIA NIM：<https://build.nvidia.com>
   - Groq：<https://console.groq.com/keys>
3. 在 **设置 → 项目文件夹** 里选团队工作的文件夹。
4. 在底部输入任务，例如「规划并做一个待办清单网页」；或者打开聊天，抛一个话题。

点任何员工或任务，都能看到具体发生了什么：读写了哪些文件、运行了哪些命令、交接给了谁、用了多少 token。

## 写一个员工

员工文件在 `%APPDATA%/OrbitOffice/office/agents/`（用过早期版本的话是 `%APPDATA%/myaioffice/...`）（设置 → 办公室与员工 → 打开文件夹）。最简单的写法：

```markdown
---
name: 文案
role: 小红书文案
team: content
color: "#f472b6"
skills: [标题, 正文, 话题标签]
keywords: [文案, 笔记, 标题, 小红书]
writes: [drafts/]
---

你负责把选题写成可以直接发布的小红书笔记。
写进 drafts/<日期>-<选题>.md：一句抓人的开头、三段短正文、5 到 8 个话题标签。
不要夸大宣传。品牌或目标人群不清楚时，先问用户一个问题。
写完交给审稿。
```

可选设置：

| 设置 | 作用 |
|---|---|
| `writes` | 能改的文件，写法同 .gitignore（`docs/`、`*.md`）。不写 = 整个工作文件夹都能改。 |
| `order` | 在办公室里坐第几个工位（1 = 第一个）。 |
| `auto-assign: false` | 只接点名给他的任务。 |
| `send-results-to` / `send-task` | 成果固定交给这位同事，交什么任务。 |
| `recheck-by` / `recheck-task` | 他要求的修改做完后，由这位同事复查一次。 |
| `needs-approval: true` | 自动模式下，他的任务要先经过你批准。 |
| `lead: true` | 主持群聊讨论并做总结。 |
| `local-only: true` | 只能碰本机，连到其他机器的命令一律拦下。 |
| `look` / `hair` | 3D 小人的配饰（`glasses`、`headset`、`cap`、`tie`）和发色。 |

参考资料（风格指南、产品资料）放在 `agents/<id>/` 文件夹里，或在设置里拖到这个员工上，他干活时会读。

从别人那里导入的员工会标记为「来自外部」：不管什么权限模式，他运行命令或使用连接器前都要先问你。

## 从源码构建

需要 Node.js 18 以上、Windows（App 基于 Electron，理论上也能打包 macOS / Linux，但没有测试过）。

```bash
npm install
npm start                  # 开发时运行
npm run dist              # 生成安装程序，在 dist/installer/
npm run portable          # 或者生成免安装的文件夹，在 dist/<名字>/
```

3D 模型用 Blender 从 `tools/blender/build_models.py` 生成，再用 `node tools/pack-models.js` 打包。

## 局限

- 干活的质量取决于你接的模型。免费模型能用，但不是最顶尖的；多人长链条协作最容易出错。
- 员工只能通过文本文件、命令和连接器工作，不能操作软件或网页界面、不能发社交媒体、不能做图片。
- 需要登录授权（OAuth）的连接器暂不支持。
- 安装程序还没有数字签名，第一次运行时 Windows 会提示「已保护你的电脑」，点「更多信息 → 仍要运行」即可。
- 本地 AI 比云端大模型弱很多，尤其是小模型，做多步骤的长任务容易出错。
- 安全测试员的命令拦截能挡住明显的联网操作，但它是护栏不是沙箱。运行来路不明的员工时，请用手动或自动模式。
